## Part 3 — Full Case Study Copy (`/work/[slug]`)

### Case 01: CJ Design System & UI Kit (`/work/cj-design-system`)
- **Client:** CJ.com · **Role:** Senior UI/UX Designer · **Timeline:** 8 Months · **Year:** 2024
- **Methods & Stack:** `Figma`, `Design Tokens`, `HubSpot CMS`, `React Specs`, `Auto-Layout`
- **01 / Problem & Context:**
  - **Problem:** While Creative Strategy defined the brand soul, engineering and marketing teams struggled with fragmented UI across HubSpot CRM templates and custom front-end frameworks. Shipping a single landing page meant manual QA loops and visual drift.
  - **Context:** The challenge wasn't aesthetic—it was operational. We needed a system that spoke Brand fluently while behaving like Code under strict CRM constraints.
- **02 / Process & Execution:**
  - **01 · Audit & Foundation — The Atomic Shift:** Replaced ad-hoc page mockups with a strict token foundation: semantic color ramps, fluid typographic scales, and an 8-pt spatial grid translated into reusable logic. (`TOKENS: 48 COLOR / 9 TYPE / 11 SPACE`)
  - **02 · System Architecture — Scalability via Variants & Constraints:** Engineered multi-state Figma components with nested auto-layout, slot patterns, and strict property matrices so marketing could assemble pages without breaking brand rules. (`64 CORE COMPONENTS · 240+ VARIANTS`)
  - **03 · The Tech Handshake — HubSpot & Framework Alignment:** Mapped every Figma property directly to HubSpot module fields and DOM constraints—achieving 1:1 visual and structural parity with production. (`FIGMA PROP ↔ HUBSPOT FIELD 1:1`)
  - **04 · Source of Truth — Governance, Do/Don't Specs & Handoff:** Delivered an annotated specification library with usage rules, spacing redlines, and interaction states—enabling autonomous shipping across teams. (`DOC COVERAGE: 100% CORE MODULES`)
- **03 / Key Design Decisions:**
  - **DEC-01 — Semantic tokens over raw hex values:**
    - *Why:* Marketing needed seasonal campaign themes without forking components.
    - *Result:* Swapping surface/accent tokens re-skins an entire module tree in minutes.
  - **DEC-02 — Constraint-first HubSpot mapping:**
    - *Why:* Design components that ignore CMS field limits break during engineering handoff.
    - *Result:* Zero rejected components in sprint QA; dev handoff friction dropped drastically.
  - **DEC-03 — Embedded redlines inside component docs:**
    - *Why:* External PDF guidelines go stale the week they are published.
    - *Result:* Living specs inside Figma kept designers and engineers on the exact same version.
- **04 / Outcomes & Impact:**
  - **`1:1`** — Figma ↔ HubSpot production parity
  - **`8pt`** — Spatial & token grid standardization
  - **`100%`** — Core marketing modules documented

### Case 02: Museu Nacional d'Art de Catalunya (`/work/mnac-information-architecture`)
> *Note: Replace or enrich any metrics below with your exact UOC project numbers when ready.*

- **Client:** MNAC · Academic / UOC Honors · **Role:** Information Architect & UI/UX Designer · **Timeline:** 4 Months · **Year:** 2024
- **Methods & Stack:** `Information Architecture`, `Tree Testing`, `Card Sorting`, `Figma`, `React`, `Tailwind CSS`
- **01 / Problem & Context:**
  - **Problem:** Museum visitors, researchers, and educators faced a deep, institutional navigation tree built around internal departments rather than visitor intent—burying tickets, collections, and current exhibitions under ambiguous labels.
  - **Context:** Developed within the MSc in UX at Universitat Oberta de Catalunya (awarded *Matrícula de Honor* in Information Architecture), combining rigorous IA research with a coded high-fidelity prototype.
- **02 / Process & Execution:**
  - **01 · IA Audit & Heuristic Inventory — Mapping Institutional Debt:** Catalogued existing nodes, depth levels, and nomenclature mismatches across visitor journeys (Plan a Visit, Explore Collection, Research). (`DEPTH REDUCED: 5 LEVELS → 3 LEVELS`)
  - **02 · Card Sorting & Tree Testing — Mental-Model Alignment:** Validated category groupings and label clarity with target users, replacing institutional jargon with task-oriented entry points. (`TASK-FIRST TAXONOMY`)
  - **03 · Structural Wireframing — Progressive Disclosure & Wayfinding:** Designed a dual-track navigation system: rapid utility access (tickets, hours, map) paired with deep editorial discovery for artworks and authors. (`DUAL-TRACK WAYFINDING`)
  - **04 · Coded Prototype — Interactive React + Tailwind Validation:** Built a functional front-end prototype in React and Tailwind CSS to test real responsive behavior, keyboard navigation, and search filtering. (`STACK: REACT + TAILWIND CSS`)
- **03 / Key Design Decisions:**
  - **DEC-01 — Intent-based top-level navigation:**
    - *Why:* Visitors think in actions ('Visit', 'On View', 'Collection'), not museum departments.
    - *Result:* Eliminated competing top-level items and clarified primary entry paths.
  - **DEC-02 — Prototyping in code (React + Tailwind):**
    - *Why:* Static artboards cannot truly test faceted collection filtering or responsive IA breakpoints.
    - *Result:* Usability sessions ran on a real browser interface with authentic interaction latency.
- **04 / Outcomes & Impact:**
  - **`Honors`** — Matrícula de Honor in Information Architecture (UOC)
  - **`5→3`** — Navigation depth levels simplified
  - **`React`** — Coded interactive prototype for usability testing

- **Methods & Stack:** `User Interviews`, `JTBD`, `Usability Testing`, `Figma`, `Design System`
- **01 / Problem & Context:**
  - **Problem:** Independent workers juggle volatile income, multi-currency invoices, and opaque quarterly tax obligations using disconnected spreadsheets and generic banking apps built for salaried employees.
  - **Context:** Master's Thesis (TFM) focused on grounding a zero-to-one fintech product in empirical user research, behavioral archetypes, and iterative usability testing.
- **02 / Process & Execution:**
  - **01 · Generative Research — Interviews, Archetypes & JTBD:** Conducted qualitative interviews and surveys with freelancers to map emotional triggers around invoicing, tax anxiety, and liquidity forecasting. (`QUAL + QUANT DISCOVERY`)
  - **02 · Problem Framing & Flows — Automated Tax & Cashflow Buckets:** Translated insights into a core product loop: every incoming payment automatically previews net spendable income vs. reserved tax provisions. (`NET-FIRST BALANCE ARCHITECTURE`)
  - **03 · Interface & System Craft — High-Precision Financial UI:** Designed a calm, tabular-numeral interface with scannable ledger cards, invoice states, and zero-jargon tax projections. (`TABULAR NUMS · AA CONTRAST`)
  - **04 · Usability Testing — Task Validation & Iteration:** Evaluated critical flows (creating an invoice, checking quarterly tax exposure, reconciling expenses) and refined micro-copy where financial terms caused hesitation. (`ITERATIVE USABILITY LOOP`)
- **03 / Key Design Decisions:**
  - **DEC-01 — 'Real Spendable' as the primary hero number:**
    - *Why:* Raw bank balances mislead freelancers into overspending money owed to taxes.
    - *Result:* Users immediately understood their true liquidity without mental math.
  - **DEC-02 — Plain-language fiscal timeline:**
    - *Why:* Accounting terminology caused drop-off during early wireframe tests.
    - *Result:* Replaced jargon with progressive explanations and visual deadline markers.
- **04 / Outcomes & Impact:**
  - **`TFM`** — Master's Thesis in UX & Product Design (UOC)
  - **`3 Flows`** — Invoicing, Tax Reserve & Cashflow Forecast validated
  - **`AA+`** — Accessible financial data density & tabular typography

  - **Context:** We needed a navigation architecture that offered deep discoverability while preserving visual clarity across desktop and mobile viewports.
- **02 / Process & Execution:**
  - **01 · The IA Challenge — Separating Corporate from User Intent:** Audited the full sitemap and replaced the flat link list with a categorical hierarchy that separates primary user tasks from secondary corporate nodes. (`SITEMAP RESTRUCTURE`)

- **03 / Key Design Decisions:**
  - **DEC-01 — Two-tier utility + discovery bar:**
    - *Why:* Mixing login/support links with service discovery created visual noise.
    - *Result:* Clean separation reduced initial cognitive load on landing.
- **04 / Outcomes & Impact:**
  - **`+3`** — New business verticals integrated without clutter
